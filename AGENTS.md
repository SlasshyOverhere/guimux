# AGENTS.md

Guidance for AI coding agents working in this repository. Mirrors `CLAUDE.md` — keep both in sync when either changes.

Guimux: lean Tauri 2 + React worktree/terminal workbench. Worktree = git dir (path + branch). Terminal = generic PTY with cwd in a worktree. Splits = N independent PTYs per worktree.

## Commands

- `npm run dev` — Vite frontend only (port 8471, `strictPort`, ignores `src-tauri`).
- `npm run tauri dev` — full app (frontend at `http://localhost:8471` per `src-tauri/tauri.conf.json`).
- `npm run typecheck` / `npm run build` — `tsc --noEmit` / `tsc --noEmit && vite build`. No lint script.
- `npm test` — frontend unit tests: `node --test` over the dependency-free modules (`updaterPolicy`, `menuPos`, `path`, `uiPrefs`, `combo`, `sidebar/statusLetter`, `sidebar/removeGuard`, `dragFile`, `terminal/osc`, `terminal/outputCodec`, `layouts`, `scripts/dailyRelease`, `explorer/markdown`, `explorer/editorBuffer`), so they run without a bundler. A new test means adding its file to that list in `package.json`, and importing with an explicit `./x.ts` extension (a bare `./x` is `ERR_MODULE_NOT_FOUND`).
- `cd src-tauri && cargo test` — Rust tests (`worktree_lifecycle`, `worktree_remove_guards_uncommitted_work`, `status_and_diff`, `encoded_command_matches_powershell`, `alias_stub_rejected`, `agent_session`, plus pty replay/epoch and fs cap tests). Single test: `cd src-tauri && cargo test <name>`.
- `.github/workflows/ci.yml` runs typecheck + `npm test` + `npm run build`, and `cargo test` on windows-latest, ubuntu-22.04 and macos-latest, on every push to main and every PR. `release.yml` only handles tagged builds.
- `npm run tauri build` — production bundle (icons + `assets/conpty/*` resources).
- `node scripts/daily-release.mjs plan|bump|notes` — release versioning used by the scheduled workflow (patch bump, conventional-commit release notes). Pure helpers are covered by `scripts/dailyRelease.test.mjs`.

## Architecture

- Backend `src-tauri/src/`: `lib.rs` registers all IPC + plugins (`store`, `notification`, `dialog`; `mcp-bridge` debug-only) and manages `PtyManager` state. `pty.rs` = generic PTY via `portable-pty` (spawn/write/resize/kill/restart; events `pty:output-{id}`, `pty:exit-{id}`). `worktree.rs` = `git worktree` CLI list/create (`guimux/<ts>-<rand>` branch, `<name>-wt` sibling dir)/remove (retried 5x for Windows locks)/merge into main|master. `git.rs` = `project_detect` (rev-parse toplevel -> git root), `git_init`, `git_status` (`-z` porcelain, rename-aware), `git_diff` (1MB cap). `fs.rs` = `fs_tree` (depth clamped 1-6, skips `.git node_modules target dist .next __pycache__`, dotfiles except `.github`)/read/write (1MB read cap, UTF-8 only). `agent_session.rs` = recovers an agent's session name from the files it writes (Claude transcript tail, Codex rollout plus its name index). `conpty_dll.rs` stages bundled ConPTY on Windows.
- Layout: topbar, worktree tab strip, terminals, file dock, sidebar. `App.tsx` is composition only — it picks which regions exist and swaps the whole workbench for the settings page when settings is open. Settings is a page, not a dialog: a 400px card cannot show a change next to the thing that caused it.
- Frontend `src/`: `bootstrap.ts` owns `useWorkspace()`: restore/persist (`persist.ts`, tauri `LazyStore guimux.json` + sync localStorage mirror, debounced 150ms), app zoom, density, the worktree loader, and the single `useWorktreeStatuses` poll. `keymap.ts` owns every shortcut — `useKeymap()` is the one dispatcher, `useBindings()` the list; `combo.ts` parses and matches accelerators and is the only place a chord is interpreted. `chrome/` = `Topbar` (the single window bar), `Welcome`, `WorktreeTabs`, `FileDock` (tree + editor under the terminals), `CheatSheet`, `WindowControls`. `store.ts` (zustand: projects, worktrees, binary pane-split tree per worktree in `layouts`, broadcast, editor/palette/settings/agent flags; every pane-field write goes through one `patchActivePane` helper; `MAX_TILES_PER_WORKTREE` and `MAX_AGENT_TILES` are exported here so the launcher's capacity meter cannot promise room the store will refuse), `project.ts` (`detectToProject` normalizes to git root). `terminal/` (`SplitView` + `TerminalPane`: xterm + fit/unicode11/serialize, a permanent per-pane header, scrollback 10k persisted to localStorage capped at 24 panes; `osc.ts` parses cwd and window title out of the output stream). `sidebar/` (`WorktreeSidebar` composes `WorktreeRow` / `RowMenu` / `DiscoveredBlock` / `CreateWorktreeForm`; letters in `statusLetter.ts`, remove guard in `removeGuard.ts`). `explorer/ExplorerPane` is a pure file tree (Monaco moved out to `editor/`), `embedded` drops its rail width and grip so it can live in the dock. `palette/Palette` (Ctrl+K: commands plus every binding as a row), `settings/SettingsPanel` + `UpdatesSection`, `agents/AgentLauncher` (tile picker), `gitOps.ts` (push/fetch/commit shared by the sidebar and the palette), `uiPrefs.ts` (guarded chrome-state storage — the only localStorage path for chrome state), `menuPos.ts` (zoom-aware menu placement), `singleFlight.ts` (one listing at a time).
- IPC: frontend never shells git; all git/pty/fs goes through `invoke` commands in `lib.rs`. Broadcast = `pty_write` to N visible panes, no prompt abstraction.

## Gotchas

- `decorations: false` — custom drag via `startDragging` on mousemove-after-press only; never drag on mousedown (swallows clicks on Windows). Dropdowns are divs with `role=button`, closed via `mousedown` capture + Escape.
- No `StrictMode` in `main.tsx` (xterm 5.5.0 dispose race logs noise in dev double-mount).
- PTY exit authority = shell process liveness (`try_wait` poll 120ms), never pipe EOF (TUIs deliver early EOF). `pty_write` passes bytes through unmodified (`\r` stays `\r`).
- Windows shell chain: `GUIMUX_SHELL` override -> real `pwsh.exe` (rejects `WindowsApps` 0-byte aliases) -> inbox `powershell.exe -NoLogo -NoExit -EncodedCommand <utf16le-base64 bootstrap>` (chcp 65001 + Set-Location) -> `cmd /K chcp 65001`.
- Closing last pane opens a fresh shell (never null layout); `worktree_list` errors propagate (never `Ok([])`) so git failures (e.g. dubious ownership) show in banner, not "Starting terminal…" hang. Plain (non-git) projects get synthetic `plain:<id>` worktree so a shell always mounts.
- PTY attach protocol: backend buffers per-PTY output (256KB ring) until frontend sends `pty_attach(id)`, which marks live + replays buffered bytes. Frontend registers `pty:output-{id}` listeners FIRST, then calls `pty_attach`. `pty_attach` errors on unknown ids -> pane spawns fresh, never blank.
- Geometry: never spawn/resize with cols/rows < 1 (backend clamps; frontend skips resize until FitAddon reports cols>=2, rows>=1). Split children keyed by pane id so splits never remount surviving panes.
- Restart reuses the numeric id with a bumped epoch; stale exit-watchers/output pumps stay silent.
- WebGL (`@xterm/addon-webgl`) is the primary renderer; `onContextLoss` disposes to canvas/DOM fallback, re-attempted on next visible mount. Hidden panes dispose WebGL, PTY stays alive.
- Debug flags: `GUIMUX_PTY_DEBUG=1` (backend spawn timestamps on stderr); `localStorage guimux-stress=1` + reload runs the dev-only split/write/close stress loop (console `[gm-stress]`; `__gmStressStop()` stops it); `localStorage GUIMUX_RESIZE_DEBUG=1` traces the terminal resize pipeline (host px -> fit grid -> debounce -> `pty_resize`, console `[gm-resize]`). That is the whole list — a new flag is a documented one, not an inline `localStorage` probe.
- A save made in the app's editor is announced to the dev server (`announceWrite` + the `guimux-ignore-app-writes` plugin in `vite.config.ts`), so it does not hot-reload the app that made it. An edit from another editor still does.
- App zoom via CSS `zoom` on `<html>` (0.5-2); terminals refit via ResizeObserver. Shortcuts are not listed here on purpose: `keymap.ts` is the list, and the cheat sheet is generated from it, so a second copy only rots.
- Releases: `.github/workflows/daily-release.yml` runs at 03:17 UTC daily. It treats release tags as the released-state record — commits already covered by a tag produce **no** release and no version bump. Only genuinely new commits on `main`, with the `frontend`, `rust (ubuntu-22.04)` and `rust (windows-latest)` CI gates green, get released: patch bump, tag, then `gh workflow run release.yml --ref <tag>`. GITHUB_TOKEN pushes emit no workflow events, so that explicit dispatch is what starts the build. A tag whose release never shipped (missing, still a draft, or published with no assets) is re-dispatched from the workflow's own `rebuild` job. `release.yml` takes an optional `release_notes` input; a manual tag push passes no notes, so that release gets an empty body.
- `cargo build --release` alone produces a BROKEN binary: tauri-build embeds devUrl `http://localhost:8471` instead of the built assets, so the window is blank and no shells spawn. Build with `npx tauri build --no-bundle`. Before trusting any measurement, confirm the app works: launch it, then `Get-CimInstance Win32_Process -Filter "ParentProcessId=<pid>"` must list `OpenConsole.exe` and `powershell.exe` as children; zero children means a blank webview.
- **Every shortcut is declared once in `keymap.ts` with a scope.** An `app` binding never fires inside `.xterm` or a text field — Ctrl+K is kill-line there and Monaco owns its own chords; a `terminal` binding exists only because the plain Ctrl+ form belongs to the shell, which is why the palette is Ctrl+Shift+K from a pane and Ctrl+K outside one. An open modal blocks everything except the chords that toggle it. The cheat sheet, the palette rows and the welcome hints are all generated from that list: add a chord there, never in an ad-hoc listener.
- **Density is a data attribute, not a class.** `data-density` on `<html>` re-declares the `--gm-fs-*`, `--gm-row-y`, `--gm-ctl-h` and `--gm-tab-h` tokens, so every `text-*`/`py-row`/`h-ctl` utility retunes at once. Density changes layout; a resized tile can move a control out from under the pointer, so reserve space rather than growing a row on interaction.
- **Pane identity is two tiers.** `launchAgents` writes `agent`, `agentBin` and `agentSince`; `session`, `sessionFrom` and `sessionKind` are live output written by the OSC sniffer or the transcript poll, which one pane per directory runs on behalf of its group. `sessionKind` is how the header tooltip admits where a label came from: `title` (the terminal title), `name`, `paired` (matched by launch order) or `prompt`. `agent`/`agentBin` persist; `session*` and `agentSince` are nulled on restore, because a stale session name and a stale launch floor are both worse than nothing.
- **Shells overwrite the window title with the cwd on every prompt.** `sessionNameFrom` in `terminal/osc.ts` is the only thing allowed to turn a title into a session name, and it rejects anything matching the cwd, any bare path, and any value with no letters. Do not widen it without a reason.
- `agent_session_titles(cwd, bin, panes)` hands every pane running `bin` in `cwd` the session that is actually its own, resolving the whole directory in one call: `panes` is `{id, sinceMs}` per pane, and the answer is `{id, title, source, matched, via}` per pane that got a label. Supporting another agent is one match arm in `agent_session.rs` plus one entry in `READABLE_AGENT_BINS` (`TerminalPane.tsx`, the frontend's poll guard), never a second command. **claude**: the project dir is `~/.claude/projects/<slug>`, slug = every non-alphanumeric character replaced with `-`, and the name is the last `{"type":"ai-title"}` record; the slug rule, the record shape and the ~99%-of-file offset (files reach 41MB, so only a 256KB tail is read) were verified against real transcripts. **codex**: the rollout at `~/.codex/sessions/YYYY/MM/DD/rollout-<ts>-<uuid>.jsonl` stores no name at all, so its opening `session_meta` record supplies `payload.cwd` (which directory), `payload.timestamp` (which session) and `payload.id`, and that id is the uuid in the filename and the key into `~/.codex/session_index.jsonl` (`{"id","thread_name","updated_at"}`), which is where the name actually lives. Both were read off the real files rather than assumed, so re-check the disk before changing any of them. **No name yet, and the prompt stands in.** `via` says which half of that a label came from, because a prompt is the user's own words rather than a name they picked: a session with no name falls back to the last prompt a human typed, flattened to one line of 60 characters with the agent's own markers (`<command-name>`, `[Image #1]`) taken off and still passed through `sessionNameFrom`, so a prompt that reads like a path or a cwd is dropped like any other label. **claude** writes a `user` record for every prompt *and* for every tool result, so records carrying `toolUseResult`, `isMeta` or `isSidechain` are skipped rather than shown. **codex** writes a typed prompt twice, and only the `event_msg`/`item_completed` `UserMessage` half is read: the `response_item` with role `user` also carries the context Codex injects at startup (`AGENTS.md` instructions, `<recommended_plugins>`, `<environment_context>`), which nobody typed. Measured over 59 rollouts on disk: every typed prompt has the first half and the injected records only the second, so a session whose first prompt has not landed yet simply has no label, which is right. A prompt is a placeholder, so `agentGroupKey` still counts that pane as pending and the group keeps polling until a real name lands. Both agents open with a record carrying the model instructions that reaches 65KB, so the head window starts at 16KB and grows until a whole line arrives: a fixed window holds one unparseable fragment and no identity at all. Both agents stamp records as UTC ISO-8601, which `iso_millis` parses and refuses to guess at: a local offset returns null. Sessions are matched on their start time, never on mtime, because a long session keeps touching its own file, and the walk is bounded (4000 entries, 80 heads read) so a ten-second poll cannot grow with history. OpenCode keeps its sessions in SQLite and stays unsupported.

## Custom Instructions

### Docs

- `AGENTS.md` and `CLAUDE.md` are one document, not two. They differ only in the title, the intro line, ASCII arrows versus typographic ones, hyphens inside numeric ranges, one extra cargo example, and a closing sync note.
- Edit `AGENTS.md`, then regenerate `CLAUDE.md` from it and confirm with `diff` that only those differences remain. Hand-editing both is how they drift.

### Comments

- Comment rarely — only where the code genuinely can't explain itself.
- One short tldr line, straight to the point. No multi-line essays, no restating the code, no commented-out code.

### Commits

- Commit after **each** fix or feature the moment it's done and verified. Never batch unrelated work: 5 issues fixed = 5 commits, so history reads as a step-by-step trail.
- Conventional Commits, lowercase, short and imperative:
  `fix(pty): drop stale exit watcher`, `feat(sidebar): prune worktrees`, `refactor(store): flatten layout helpers`.
- Subject <= ~60 chars, no trailing period. Body optional and only for the *why* — 1-2 short lines max.
- **No git attributions, ever.** No `Co-Authored-By`, no "Generated with …", no emoji footers, no tool signatures. Commit as the repo's normal author.
- **Commit only.** Never `git push` or any remote-affecting command without explicit user approval.

### Best Practices (this app)

- **All OS work goes through Rust.** The frontend never shells out to git/fs/pty: add a `#[tauri::command]` in the matching module, register it in `lib.rs`'s `invoke_handler`, call it via `invoke<T>("name", { camelCaseArgs })`.
- **Keep the wire contract in sync.** Rust serde structs and `src/types.ts` mirror each other (snake_case fields) — change both in the same commit.
- **Propagate errors, don't swallow them.** Backend errors surface in the banner; returning `Ok([])`/empty on failure hides real problems (e.g. git dubious ownership) and strands the UI on "Starting terminal…".
- **PTY rules:** register `pty:output-{id}` listeners *before* `pty_attach`; never spawn/resize below 1 col / 1 row; exit authority is process liveness, not pipe EOF; `pty_write` bytes pass through unmodified.
- **Pane identity:** key split children by pane id; never remount a surviving pane; never leave a layout null (closing the last pane opens a fresh shell).
- **Persist through `store.ts`** (zustand) + `persist.ts` (`LazyStore` + debounced mirror) — no ad-hoc storage.
- **Windows first.** File locks (retried removes), path separators, the shell fallback chain and ConPTY staging all matter; prefer `portable-pty` APIs over spawning shells.
- **Stay lean.** Match the terse existing style; don't add a dependency, abstraction, or config knob for a one-off. No `StrictMode` (xterm dispose race). There is no lint tooling — don't assume it.
- **One design system.** The `--gm-*` tokens in `styles.css` are the only color source; the `@theme` block beside them resolves `ink-*`/`surface-*`/`clay-*` to those tokens (Tailwind v4 is CSS-first, so there is no `tailwind.config.js`), so never hardcode a hex or a `white/*` opacity in a component. Reuse a `gm-*` primitive (`icon-btn`, `btn`, `btn-ghost`, `dialog`, `scrim`, `inset`, `rule`, `rule-top`, `divider-l/r`, `field`, `menu`, `menu-item`, `row`, `wt-row`, `tab`, `pane-tools`, `pane-in`, `sect`, `meta`, `item`, `seg`, `kbd`, `close-btn`) instead of hand-rolling one — and add a primitive rather than a fourth copy. They live in `@layer components` on purpose: a utility class on the same element must still win.
- **Show the constraint, don't hide it in small print.** If the store clamps or refuses (12 tiles, 6 per agent, a 256KB tail), the UI says so before the user commits to a choice — a meter beats a paragraph, and a wrong label beats neither.
- **Check the disk before you parse it.** Field names, path layouts and record offsets in someone else's tool are not guessable: read the real files first, assert the result in a test, and say plainly when the format does not exist.
- **Match by order only when the count forces it.** Two things that are identical apart from time (two agents in one directory, two identical rows) can be told apart by position if and only if nothing else is missing or extra; if the counts disagree, name nothing. Say which kind of match you used where the user can see it (a pane header reading `matched by launch order` beats a silently wrong name).
- **A stand-in says what it is.** A prompt shown where a name would go is fine while the header admits it is the last prompt and not a name; the poll keeps running until the agent names the session, and a real name always wins over the prompt it stood in for.
- **No runtime CDNs.** The packaged CSP is `script-src 'self'`, so anything fetched at runtime (Monaco's AMD bundle is the precedent) breaks in `tauri build` while working fine under Vite. Bundle it and configure `loader.config({ monaco })` instead of letting a loader reach out.
- **Verify before committing:** `npm run typecheck` after frontend edits, `cd src-tauri && cargo test` after Rust edits, `npm run build` when in doubt.
